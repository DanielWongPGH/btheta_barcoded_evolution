## Metagenomics

This directory turns paired metagenomic FASTQs into population-level mutation
and coverage timecourses. All machine-specific input, output, reference, and
executable paths belong in the repository-root `project_config.yaml`; the
scripts and checked-in metadata can be addressed from any working directory.

### Inputs

- Paired R1/R2 metagenomic FASTQs named `<sample>_R1_001.fastq[.gz]`
  and `<sample>_R2_001.fastq[.gz]`. Trimming accepts either form and never
  compresses or otherwise modifies the raw inputs.
- `E1_MGX_fastq_stems.txt` and `E2_MGX_fastq_stems.txt`. The first line of
  each manifest is its FASTQ directory and the remaining lines are sample
  stems.
- `population_samples.csv`, generated by `make_timecourse_fastq_lists.py`.
  It assigns FASTQ samples and timepoints to populations; it is not an
  independently maintained sample manifest.
- `genome_positions.bed`, defining the regions reported by the coverage
  timecourse.
- Matching GenBank and FASTA references configured under
  `raw_processing.metagenomics.reference`.
- Trimmomatic, breseq/gdtools, SAMtools, Java, bzip2, mikefarah/yq v4, and the
  legacy Python 2 environment in `../environment-python2.yaml`.

`make_timecourse_fastq_lists.py` uses the historical filename parser from the
archive-deposition utilities. Pass the directory containing the
`prep_fastq_for_SRA` package through `--parser-root`; its location is not
embedded in this repository.

### Configure and generate metadata

Replace the metagenomics placeholders in `../../project_config.yaml`, including
the scratch/output root, manifest FASTQ directories, references, executables,
Slurm resources, and module names. Metagenomics currently requires
`execution.scheduler: slurm`; set `execution.load_modules: false` when all
configured executables are already available, as with the Bar-seq workflow.
Set `execution.python` to the Python 3 executable used by metadata discovery
and coverage summaries; the legacy timecourse code separately uses
`python2.executable`.
Then update the manifest headers:

```bash
bash raw_processing/process_metagenomics/generate_fastq_stems.sh \
    project_config.yaml
```

Regenerate `population_samples.csv` after changing the sample manifests:

```bash
python raw_processing/process_metagenomics/make_timecourse_fastq_lists.py \
    --parser-root /path/to/archive-utilities
```

The generator reads FASTQ directories from the manifest headers and writes
`population_samples.csv` beside the script by default. Use `--e1-manifest`,
`--e2-manifest`, or `--output` to override those portable defaults.

Activate the frozen parser environment before the processing stages:

```bash
conda env create -f raw_processing/environment-python2.yaml
conda activate btheta-remote-python2
```

Set `raw_processing.metagenomics.python2.executable` to the executable from
that environment.

### Ordered workflow

The examples below run from the repository root. `POPULATION` may be one
population or a comma-separated list. `SEQUENCE_TYPE` is one of the subsets
understood by `population_parameters.py`, including `non_stragglers`,
`stragglers`, and `non_straggler_non_clones`.

1. Trim adapters. Run this once for each configured FASTQ directory and wait
   for all array jobs to finish.

   ```bash
   bash raw_processing/process_metagenomics/step0_trim_adapters.sh \
       project_config.yaml /path/to/untrimmed-fastqs
   ```

   The wrapper discovers samples, writes a temporary sample list, and places
   trimmed reads in `<untrimmed-fastqs>_trimmed`.

2. Run the first breseq pass in polymorphism mode.

   ```bash
   bash raw_processing/process_metagenomics/step1_breseq_genomes.sh \
       project_config.yaml POPULATION SEQUENCE_TYPE
   ```

3. Merge candidate junction evidence within each population.

   ```bash
   bash raw_processing/process_metagenomics/step2_merge_candidate_junctions.sh \
       project_config.yaml POPULATION SEQUENCE_TYPE
   ```

   This produces `<population>_merged_breseq_output.gd` in the configured
   first-pass breseq directory. Step 3 currently rebuilds this union as well,
   so step 2 can be retained as an inspectable checkpoint.

4. Run breseq again using the population-wide junction evidence.

   ```bash
   bash raw_processing/process_metagenomics/step3_rebreseq_genomes.sh \
       project_config.yaml POPULATION SEQUENCE_TYPE
   ```

5. After every rebreseq job has produced its BAM, evidence GD, and summary
   JSON, launch the mutation and coverage branches. They are independent.

   ```bash
   bash raw_processing/process_metagenomics/step4_create_distributed_timecourse.sh \
       project_config.yaml POPULATION SEQUENCE_TYPE

   bash raw_processing/process_metagenomics/step4b_make_coverage_timecourse.sh \
       project_config.yaml POPULATION SEQUENCE_TYPE
   ```

   The first command writes numbered mutation-timecourse chunks. The second
   writes `<population>_coverage_timecourse.txt` with total reads, aligned
   reads, genome-wide coverage, and BED-region depths.

6. Once all mutation chunks exist, merge them with the rebreseq junction and
   indel evidence.

   ```bash
   bash raw_processing/process_metagenomics/step5_create_merged_timecourse.sh \
       project_config.yaml POPULATION SEQUENCE_TYPE
   ```

   The result is `<population>_merged_timecourse.bz2` in the configured
   timecourse directory.

7. Export the final products into the local paths configured at
   `local.mgx_timecourses` and `local.breseq_timecourses`. The historical
   copy/decompression and `all_bam_coverage.txt` assembly step is not currently
   represented by a script, so confirm the filenames and sample ordering
   expected by notebooks `4b_invivo_metagenomics.ipynb`,
   `invivo_metagenomics.ipynb`, and `4c_BAM_coverages.ipynb`.

### Completion checks

- Every requested sample has paired trimmed FASTQs and a `.finished` marker.
- Every first-pass sample has `output/evidence/evidence.gd`.
- Every population has a merged candidate-junction GD.
- Every rebreseq sample has `data/reference.bam`,
  `output/evidence/evidence.gd`, and `output/summary.json`.
- Every expected genome interval has one mutation-timecourse chunk.
- Each population has a coverage timecourse and a nonempty merged `.bz2`
  mutation timecourse.

### Scripts

| Script | Role |
|---|---|
| `generate_fastq_stems.sh` | Populate manifest FASTQ directories from configuration |
| `make_timecourse_fastq_lists.py` | Generate `population_samples.csv` from the E1/E2 manifests |
| `step0_trim_adapters.sh`, `step0_trim_adapters.sbatch` | Discover samples and trim paired reads |
| `step1_breseq_genomes.sh`, `step1_breseq_genomes.sbatch` | Run first-pass polymorphism-mode breseq |
| `step2_merge_candidate_junctions.sh` | Union junction evidence within populations |
| `step3_rebreseq_genomes.sh`, `step3_rebreseq_genomes.sbatch` | Re-run breseq with population-wide evidence |
| `step4_create_distributed_timecourse.sh`, `step4_create_timecourse.sbatch` | Build mutation-timecourse chunks |
| `step4b_make_coverage_timecourse.sh`, `step4b_make_coverage_timecourse.sbatch` | Build coverage timecourses |
| `step5_create_merged_timecourse.sh` | Merge chunks with rebreseq junction/indel evidence |
| `population_parameters.py` | Select ordered samples for populations |
| `parse_file.py`, `step4_create_timecourse.py`, `step5_create_breseq_timecourse.py` | Frozen Python 2 timecourse parsers |
| `../parse_config.sh` | Load the metagenomics section of the shared YAML configuration |
